Data Integrity & Verification

How this app proves its numbers are real — and how you can independently verify every one of them.

1 · Every number carries its own evidence

Every metric stored in this app is saved with four fields: source, geographic region, time period, and collection timestamp. Open any title's detail page and you'll find a provenance table. If a field were missing, the number would not be displayed at all.

2 · You can re-verify every source yourself — right now, for free

The app has no private data. All three sources are public:

  • TMDB — metadata, rating, popularity. Anyone can call the same public API endpoint and compare the value with ours. They must match exactly, because we store what the API returned, unmodified.
  • IMDb ratings & vote counts — come from IMDb's own free official dataset at datasets.imdbws.com. Download title.ratings.tsv.gz, look up the title's IMDb id (shown on our detail pages), and compare.
  • Google Trends — anyone can search the same title at trends.google.com and see the same relative-interest pattern for the last 7 days.

3 · The app is structurally unable to invent data

The database schema rejects any metric row without a source and a collection timestamp. When a provider fails or a metric is unavailable, the app stores/renders "Data unavailable" — it never interpolates, estimates, or fabricates a value. Historical charts are drawn only from snapshots actually collected at listed timestamps; no synthetic history is ever generated.

4 · Honest, documented limitations

  • Google Trends gives relative interest (0–100) within a query window, not absolute search counts — displayed and labeled as such.
  • TMDB popularity is TMDB's own metric — it is not viewership, and this app never claims "views".
  • Values drift by design — sources are live. A rating may change at TMDB after we collect it; that's why every value is stamped with its collection time rather than silently overwritten as "now".
  • Rotten Tomatoes & Letterboxd publish no official public API, so no numbers are shown for them — shown as "Data unavailable" rather than estimated.
  • Google Trends is queried via an unofficial client and is occasionally rate-limited; those runs simply collect nothing.

5 · How to challenge a specific number

Pick any title, note its provenance (source + timestamp), then query that source directly for that date. If the source shows a different value, the collection-time stamp will explain the difference; if you find a value that cannot be reproduced from any source, that would be a genuine bug — the architecture makes such a bug auditable and traceable.

All metrics carry their source, region, period, and collection timestamp. No data is simulated. Where a source does not provide a metric, it is shown as “Data unavailable”.
